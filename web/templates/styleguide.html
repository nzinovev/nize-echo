Почему я перестал писать посты через git

Статический генератор хорош, пока ты не замечаешь, что между идеей и публикацией стоят коммит, CI и деплой.

Мой прошлый сайт был собран на статическом генераторе. Каждый пост — markdown-файл в репозитории, каждая правка опечатки — новый деплой. Технически это красиво, но на практике я начал откладывать заметки, потому что их публикация ощущалась как релиз.

Контент в базе, код в git

Новое правило простое: деплой нужен только когда меняется код. Пост живёт в Postgres, редактируется в админке и становится публичным сразу после нажатия кнопки или в назначенное время.

func (s *Store) Published(ctx context.Context, lang string) ([]Post, error) {
    // отложенные посты появляются сами: фильтр по publish_at
    return s.q.ListPublished(ctx, lang, time.Now())
}
Отложенная публикация не требует планировщика — достаточно сравнить время в запросе.

«Хороший инструмент для письма — тот, о котором не думаешь, пока пишешь.»

Что получилось

Через месяц на новом движке:

  • черновики и отложенная публикация без отдельных задач по расписанию;
  • картинки вставляются прямо в редактор;
  • посты группируются по контекстам, а не только по тегам.
  • #go
  • #postgres
  • #блог

Короткие мысли между постами — в Telegram.
